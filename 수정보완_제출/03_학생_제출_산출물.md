## 3. 오류 수정 보고

### 결함 1

| 항목 | 작성 내용 |
|---|---|
| 결함 ID | BUG-01 |
| 선택자 | `.con` |
| 문제 선언 | `max-width: var(--containner);` (`--container` 변수명 오타: n 중복) |
| 화면 증상 | CSS 변수 미인식으로 최대 너비(1600px) 제한 및 중앙 정렬 여백이 풀려 좌우 여백이 정답 화면과 불일치 |
| 진단 방법 | 개발자 도구(F12) Elements 탭에서 `.con`의 `max-width` 속성 검사 시 정의되지 않은 변수로 비활성화(무효) 확인 |
| 수정 선언 | `max-width: var(--container);` |
| 수정 전/후 증빙 | `./수정보완_제출/1번 수정 전.png`, `./수정보완_제출/1번 수정 후.png` |

| 항목 | 작성 내용 |
|---|---|
| 결함 ID | BUG-02 |
| 선택자 | `.grid-5` |

## 6. 최종 회고

- 가장 찾기 어려웠던 오류와 이유: BUG-03(1600px 이하 가로 스크롤 발생). 미디어 쿼리나 개별 그리드 요소의 overflow 문제로 추정하였으나, 기본 스타일에 정의된 `body { min-width: 1600px; }`로 인해 전체 뷰포트 너비가 고정되었던 것이 원인이었으며, 개발자 도구의 Computed 스타일 분석을 통해 원인을 찾아 해결할 수 있었습니다.
- CSS 파일 분리 기준을 정한 방법: 02_학생용_과제안내서의 8단계 기준에 맞추어 [기본 리셋/폰트(`normal.css`) → 원시 토큰(`root.css`) → 의미 기반 시맨틱 토큰(`component.css`) → UI 단위 컴포넌트(`btn_cpn.css`, `item_cpn.css`) → 레이아웃/그리드(`layout_cpn.css`) → 섹션별 스타일(`style.css`) → 반응형 분기(`media.css`)]의 체계적인 디자인 시스템 계층 구조를 적용하였습니다.
- 파일 분리 후 캐스케이드 문제를 예방한 방법: 전역 기본 스타일과 토큰 변수를 최상단에 두고, 이를 참조하는 컴포넌트와 레이아웃, 그리고 최종적으로 특정 섹션 커스텀 및 미디어 쿼리가 오버라이드할 수 있도록 `index.html`의 `<link>` 태그 로딩 순서를 엄격히 제어하였습니다.
- 다시 수행한다면 개선할 점: CSS 변수 네이밍 및 컴포넌트 클래스명을 일관된 방법론(BEM 등)으로 더욱 정교하게 구성하고, 반복되는 스타일 유틸리티 클래스를 모듈화하여 유지보수성을 극대화하고자 합니다.
